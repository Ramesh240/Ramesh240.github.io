 ### System Design Interview Roadmap 🚀

**Phase 1 — Foundations**
1. What is System Design?
2. Functional vs Non-functional requirements
3. Scalability
4. Availability & Reliability
5. Latency & Throughput
6. CAP theorem
7. Horizontal vs Vertical scaling
8. Load balancing
9. Stateless vs Stateful services
10. Monolith vs Microservices

**Phase 2 — Core Building Blocks**
11. REST APIs
12. Databases — SQL vs NoSQL
13. Database indexing
14. Replication
15. Sharding
16. Partitioning
17. Caching
18. Redis
19. Message queues
20. Kafka / event-driven architecture
21. CDN
22. Object storage
23. API Gateway
24. Service discovery

**Phase 3 — Distributed Systems**
25. Consistency models
26. Strong vs eventual consistency
27. Distributed transactions
28. Idempotency
29. Retry & exponential backoff
30. Circuit breaker
31. Rate limiting
32. Fault tolerance
33. Leader election
34. Distributed locking
35. Eventual consistency
36. Data replication strategies

**Phase 4 — Practical Design**
We'll design systems such as:

- URL Shortener
- Rate Limiter
- Notification System
- File Storage System
- E-commerce System
- Food Delivery System
- Ride Booking System
- Chat/Messaging System
- Social Media Feed
- Video Streaming System
- Payment System
- Ticket Booking System
- Job Scheduler
- Logging/Monitoring System

**Phase 5 — LLD**
Since you're a .NET developer, we'll also cover:

- SOLID
- Design patterns
- Class diagrams
- Interfaces
- Dependency Injection
- Repository/Service patterns
- Strategy
- Factory
- Observer
- Builder
- State
- Singleton
- Chain of Responsibility

And we'll implement selected LLD problems in **C#**.

### How we'll study each day

**Day N**
- 📚 Concepts
- 🧠 Interview intuition
- 🏗️ Architecture diagrams
- 💻 C#/.NET/Azure examples where relevant
- ❓ 10 interview questions
- 🎯 One design exercise
- 📝 Interview notes
- 🔥 Common follow-up questions

For System Design, I don't want you to memorize diagrams.

We'll repeatedly follow this interview framework:

**Requirements → Scale → APIs → Data Model → High-Level Architecture → Deep Dive → Bottlenecks → Trade-offs → Failure Handling**

That framework will eventually let you approach unfamiliar design questions confidently.
